# UI_SOCIAL_NETWORK_PROJECT
# Автоматизированный фреймворк для тестирования социальной сети (Selenium + Python)

Профессиональный, масштабируемый фреймворк для сквозного (E2E) и мультиюзерного тестирования веб-интерфейса социальной сети. Проект построен на современном стеке технологий с использованием продвинутых паттернов проектирования, контейнеризации и настроенным CI/CD пайплайном.

## 🛠 Стек технологий

*   **Язык программирования:** Python 3.12
*   **Движок автоматизации:** Selenium WebDriver (v4)
*   **Тестовый фреймворк:** Pytest (с плагинами `pytest-rerunfailures`, `pytest-xdist`)
*   **Паттерны проектирования:** Page Object Model (POM), Page Components, Fixture Factory
*   **Контейнеризация и Оркестрация:** Docker, Docker Compose, Selenium Grid
*   **Отчетность и CI/CD:** Allure Framework, GitHub Actions, GitHub Pages
*   **Уведомления:** Telegram Bot API (интеграция через Pytest Hooks)
*   **Генерация данных:** Faker

## 🚀 Ключевые инженерные решения

### 1. Паттерн Page Components & Инкапсуляция состояний
Боковое меню выделено в изолированный компонент `SidebarComponent`. Реализован «умный» метод `click_menu_item`, который перед кликом анализирует DOM-дерево и состояние меню (свернуто/развернуто). Если раздел закрыт, компонент сам раскрывает его и дожидается окончания анимации перед кликом. Тесты полностью изолированы от логики состояний интерфейса.

### 2. Отказоустойчивая фабрика сессий (Cookie-Driven Automation)
Для ускорения прогона тестов реализован механизм авторизации через файлы куки. Фреймворк снабжен интеллектуальной системой валидации: при старте теста он подкидывает старые куки, но если они были отвергнуты сервером (например, после ежедневной очистки базы данных на тестовом стенде), хелпер перехватывает ошибку, молча удаляет «протухший» файл, производит чистый UI-вход, сохраняет свежие куки и беспрепятственно продолжает тест.

### 3. Мультиюзерное тестирование (Multi-Browser)
Для полноценного сквозного тестирования чата реализован запуск двух независимых параллельных инстансов WebDriver (`admin_browser` и `friend_browser`). Фикстуры изолируют сессии кук для каждого пользователя, позволяя симулировать реальный диалог в реальном времени (Админ отправляет сообщение в одном окне, Друг мгновенно считывает его в другом).

### 4. Динамический XPath и Flaky-защита
Для обработки динамических ID сообщений в чате применен гибкий XPath-локатор с использованием функций `starts-with` и `[last()]`. Это позволяет Selenium мгновенно забирать текст самого свежего сообщения на экране без выкачивания тяжелых коллекций элементов в память Python. Для борьбы с сетевыми задержками внедрен плагин `pytest-rerunfailures` с задержкой между перезапусками.

## 📈 CI/CD Пайплайн и Отчетность

Проект полностью интегрирован в облачную инфраструктуру **GitHub Actions**:
1. По кнопке `workflow_dispatch` поднимается чистый раннер `ubuntu-latest`.
2. Поднимается связка Docker-контейнеров: изолированный сервер `standalone-chrome` (Selenium Grid) и контейнер с тестами.
3. Все секреты безопасности (`TOKEN`, логины, пароли) прокидываются из GitHub Secrets на лету.
4. После прогона контейнер с установленным Allure CLI генерирует актуальный отчет, подтягивает историю прошлых запусков (`allure-history`) и деплоит результат на **GitHub Pages**.
5. Хук `pytest_terminal_summary` в `conftest.py` агрегирует результаты прогона по каждому файлу и отправляет красивую HTML-сводку со статистикой и ссылкой на отчет в целевой **Telegram-чат**.
6. При падении любого теста хук `pytest_runtest_makereport` автоматически делает скриншот экрана в оригинальном разрешении и намертво прикрепляет его к шагу в Allure.

## 📝 Известные ограничения тестового стенда

Тестируемая песочница социальной сети полностью очищает свою базу данных и сессии каждую полночь. По этой причине сохраненные файлы кук актуальны строго в рамках одного дня. Пайплайн спроектирован так, что при первом утреннем запуске тесты автоматически обновят файлы сессий через UI-авторизацию, не требуя ручного вмешательства в код фреймворка.

В папке `helpers/mail_helper.py` и корневом `mail.py` сохранена чистая, задокументированная интеграция с API MailSlurp, демонстрирующая навык работы с динамическими почтовыми инбоксами, обработкой REST-запросов и регулярными выражениями для извлечения валидационных ссылок.
